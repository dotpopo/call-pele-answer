# 拆块与路由细则


## 形式速查表（从 SKILL.md 移来）

1. **核心结论**：一到两句，永远是第一块，永远是文字。
2. **读者要理解的几件事**：每件一块，3–8 块，一块只回答一个子问题。
3. **每块的理解障碍**：按下表定形式；障碍不在表里，就用文字。

| 信息形状 | 障碍 | 形式 |
|---|---|---|
| 结论、定义、建议、单个事实 | 无 | 文字 |
| 有先后的动作 | 记住顺序 | `1. 2. 3.`；分支多用 `flowchart` |
| 结构、依赖、架构 | 靠“它/上面那个”指代 | `flowchart` `architecture-beta` `C4Context` `block` |
| 按时间来回的消息 | 先后与方向 | `sequenceDiagram` |
| 状态与转移、生命周期 | 哪些状态能到哪 | `stateDiagram-v2`（按状态分组的任务用 `kanban`） |
| 层级、目录、分类 | 嵌套深度 | `mindmap` `treeView-beta` `treemap-beta` |
| 实体与字段、类 | 关系基数 | `erDiagram` `classDiagram` |
| 历史、阶段、排期 | 时间轴 | `timeline` `gantt` `gitGraph` |
| ≥2 个选项 × ≥2 个可比属性（≥6 格） | 横向对照 | 表格，状态列写 `ok/no/warn`。按位置排的规则（→ 流程图/时序图标注）、互不相干的数字（→ 各归原块）、2–3 个长选项（→ tabs）都不是对照 |
| 几个备选答案，各有细节 | 一次只看一个 | `tabs` |
| 数量、趋势、占比、流向 | 量级 | `xychart` `pie` `sankey` `radar-beta` `quadrantChart`（须有真实数据或标“示意”） |
| 原因归类、取舍空间、定位 | 全局视野 | `ishikawa-beta` `quadrantChart` `venn-beta` `wardley-beta` `cynefin-beta` |
| 改一个参数会怎样 | 只能想象 | `slider` |
| 随时间展开的机制 | 要看着它变 | `steps` |
| 项目里真实的代码 | 防编造 | ```` ```ts src=路径 lines=10-30 ```` |
| 必须先提醒的风险 | 漏看 | `callout warn` |

其余图（`usecase-beta` `requirementDiagram` `packet` `railroad-ebnf-beta` 等）和反例见 `references/routing.md`。

**升级纪律**：更重的形式必须消除一个具体障碍，“显得单薄”不是理由。一句话能说清就不画图；一张图超过 9 个节点或 12 条连线，就拆成总览加细节（`route/too-complex`）。

## 为什么按块路由

解释的形式有一条阶梯：文字 → 图 → 网页 → 解释视频。常见做法是“给整个回答选一个格式”。但一个真实的回答里，结论适合一句话，流程适合一张图，取舍适合一张表，参数影响适合一个滑块。整体选一个格式，必然有几块用错形式：要么全是文字墙，要么为一句结论也画一张图。

所以本技能分两层决策：

1. **块的形式**：每块按信息形状和理解障碍单独选（下面的形式速查表）。
2. **载体**：所有块定完后，再看要不要出页面（SKILL.md「出页还是聊天」）。

## 拆块方法

1. 写出核心结论（1–2 句）。
2. 列出读者为了相信并使用这个结论，必须理解的子问题。每个子问题是一块。
3. 合并：两块总是一起读，就合成一块。删除：去掉后结论不受影响的块。
4. 排序：结论 → 机制/结构 → 证据/比较 → 操作步骤 → 边界与风险。
5. 给每块定形式。同一种形式连续出现 3 次以上时，检查是否有一块其实更适合另一种形式。

块数：页面 3–8 块；聊天 1–4 段。

## 形式判定：先问障碍，再选形式

| 问自己 | 是 → |
|---|---|
| 读者要靠“它/前者/上述”在脑子里连线吗？ | 图 |
| 读者要横向比较同一维度吗？ | 表格 |
| 读者要想象“改了会怎样”吗？ | 滑块 |
| 读者要看着它一步步变化吗？ | 分步 |
| 读者一次只关心几个备选中的一个吗？ | 标签页 |
| 都不是 | 文字 |

自动路由覆盖上表全部类型：结构类（层级、结构、状态、时序、战略图、语法）门槛更低（置信 ≥ 0.45），块里列出 3 项以上时再加分；一句话能说清的短块仍保留文字。

通用规则：

- 一张图只讲一件事。超过 9 个节点或 12 条连线，拆成总览加细节或用 `subgraph` 折叠。
- 节点文字短；含括号、冒号、引号时用 `A["f(x): 值"]`。
- 不在图里写 `style`/`classDef` 固定颜色：固定色不随主题切换。要强调或分类，用语义类：`class A,B bad`（或 `A:::ok`）。状态类 `bad/bug` 红框、`ok/fixed` 绿框、`warn` 黄、`new` 蓝、`muted` 灰；分类用色名 `blue/green/red/yellow/orange/cyan/purple/magenta` 浅底。颜色随主题和调色器走。
- 用了语义类就加图例：图里写一行 `%% 图例: bad=违反规则; fixed=已修复`，页面在图上方画同色标签。
- 复杂状态图（复合状态、`<<choice>>` 分支、`note right of X`、跨组迁移）直接用 `stateDiagram-v2`，一张图讲一个场景；配色表达“哪类状态 / 哪条路径有问题”。
- 只有最复杂的那张图需要提示读者先看哪里时，写成图前的一句普通话，不用“看哪里：”标签，一页最多一次。

## 交互块

- **slider**：2–7 个取值。每个取值写结果（一两句）+ 可选一张图。取值是离散的，不在页面里执行任意公式：模型事先算好或标“示意”。
- **tabs**：2–5 个标签。每个标签结构相同（同样的小标题顺序），方便来回对照。
- **steps**：8–15 拍适合一个机制。每拍只变一样东西；旁白 1–2 句。默认进入视口自动播放，尊重“减少动态效果”设置；`autoplay=off` 关闭。

## 视频

- **第 0 级（默认）**：`steps` 分步播放页。离线、文字可选中、每拍精度等于稿件。
- **第 1 级（仅明确要文件时）**：先检查 ffmpeg、Manim、TTS 是否真的可用、是否有授权。缺什么就说缺什么，退回第 0 级，并把它叫“分步页/分镜”，不叫“视频”。
- 不要做视频：一张图加几句话就能讲清；用户随口一问；内容是要检索的参考资料（命令、参数表）。

## 反例

- 为“`ls -a` 能看隐藏文件吗”出一页 → 一句话回答。
- 结论、原因、步骤全写成段落，再在末尾附一张总图 → 图应该替换掉描述流程的那段文字，而不是重复它。
- 三个选项、两个维度做成三张标签页 → 一张 3 行表格更快。
- 没有数据却画“增长趋势” → 删掉，或标“示意”并说明只演示形状。
- 一页 12 块 → 拆成两页，或删掉不影响结论的块。

## 多视图（views）与组合器

- 组合器按整页打分：分类器给的概率是底分，再减去惩罚——与上一块同形式、超出交互预算（默认每页 2 个 slider/tabs/steps）、一句话能说清、窄屏不适合宽表格/架构图。分数低于 0.5 就用文字。
- 一块内容有两种以上可行的看法（如时间线 ↔ 表格、饼图 ↔ 表格、状态图 ↔ 转移表、步骤 ↔ 流程图），写成 ```` ```views ````，最多 3 个，最后一个通常是“原文”。
- views 和 tabs 的区别：views 是同一内容的不同表示；tabs 是不同的答案。

## 常见语法坑

- `xychart` 的中文类目必须加引号：`x-axis ["一月", "二月"]`。
- 节点文字含括号、冒号：`A["f(x): 值"]`。
- `stateDiagram-v2` 的状态名不要带标点。
