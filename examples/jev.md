---
title: Jev 是什么
subtitle: TypeSafe 的第一个 System One 模型
source: docs.typesafe.ai · typesafe.ai · 2026-10-23
---
Jev 不写文字，只做决定。你给它一段状态和几个带类型的问题，它返回结构化答案和概率，程序直接拿来分支。

## 一次调用发生了什么

```views
=== 时序图
~~~mermaid
sequenceDiagram
  participant P as 你的程序
  participant J as Jev
  P->>J: POST /v1/systemone（状态 + 问题）
  Note over J: 并行采样器一次评估全部问题
  J-->>P: 每个问题的答案 + 概率
  alt 置信度高
    P->>P: 直接执行
  else 置信度低
    P->>P: 交给人复核
  end
~~~
=== 步骤
1. 程序把状态和问题发给 `POST /v1/systemone`。
2. Jev 用并行采样器一次评估全部问题。
3. Jev 返回每个问题的答案和概率。
4. 程序按置信度决定：直接执行，或交给人复核。
```

问题数量几乎不影响耗时，因为所有问题在一次查询里并行评估。

## 三种问题类型

| 类型 | 问的是 | 返回 | 例子 |
|---|---|---|---|
| choice | 从你定义的选项里选一个 | 选项 + 每个选项的概率 | 这块内容用表格、时间线还是流程图 |
| score | 在有序量表上的位置 | 分数 + 概率 | 这段文字难读程度 0–2 |
| noul | 一个陈述为真的概率 | 0 到 1 之间的数 | “这段文字给出了具体数字” |

## 和聊天大模型有什么不同

| 维度 | 聊天大模型 | Jev |
|---|---|---|
| 训练方法 | RLHF：对齐人的偏好 | RLCD：为校准决策做的强化学习 |
| 输出 | warn 给人读的文字，要解析 | ok 类型化的值，不用解析 |
| 编造 | warn 可能编造 | ok 答案只能是你定义的选项 |
| 置信度 | no 往往过度自信 | ok 每个答案带校准过的概率 |
| 能做什么 | ok 写作、写代码、对话 | no 不写文字、不写代码、不聊天 |

```callout note 不是聊天模型的替代品
Jev 不能放进 Claude Code 或 Cursor 当底层模型。正确用法是让大模型写代码，代码在需要判断的地方调用 Jev。
```

## 它不擅长什么

Jev 1.13 的官方说明列出了这些弱点：

- 需要多层间接推理的任务。
- 需要精确数值的任务。
- 一个问题里藏了几个判断。拆成几个问题。
- 状态里塞了问题用不到的内容。只给需要的部分。
- 理解比较字面。
- 只接受文本，不接受图片、音频和视频。
